ENEMY PARAMETER / TUNING KNOB IDEAS

General principle:
Add parameters that change combat identity and behaviour, not just raw stat multipliers. Keep optional structs omitted when an enemy uses defaults so registrations stay readable.


1. RANGE / COMBAT DISTANCE

Possible generic range parameters:
- preferred
- preferred_tolerance
- preferred_variance

Meaning:
preferred = where the enemy generally wants the fight to happen.
preferred_tolerance = loose dead-band around preferred range.
preferred_variance = one-time per-enemy variance so identical enemies do not all sit at exactly the same distance.

Example:
range: {
    detection: 1120,
    combat: 760,
    preferred: 520,
    preferred_tolerance: 90,
    preferred_variance: 70,
    backaway: 260,
    forget: 1320,
    wander: 0,
    alert_share: 1200
}

Potential behaviour:
- farther than preferred + tolerance -> bias inward
- inside preferred band -> no radial correction / let combat script do its thing
- closer than preferred - tolerance -> bias outward
- inside backaway -> hard emergency retreat

Important:
Randomize preferred range once on spawn, not every frame, otherwise enemies will jitter.

18. STRUCTURE / ORGANIZATION PRINCIPLE

Do not put every possible knob directly into every enemy definition.
Prefer optional grouped structs so simple enemies stay compact.

Example:
movement_controller: {
    asteroid_response: AsteroidResponse.AVOID,
    facing: {...},
    strafe: {...},

    tactics: {
        preferred_distance: 760,
        distance_tolerance: 100,
        combat_speed_scale: 0.85
    }
}

Omit entire optional structs when defaults are enough.


HIGHEST-VALUE IDEAS TO CONSIDER FIRST

1. Generic preferred combat range + tolerance + one-time variance
2. Attack repeat penalty / recent attack memory
3. Richer per-attack conditions based on target shield, hull, speed, state, terrain
4. Movement scaling while firing
5. Destructible / targetable hardpoints
6. Critical-health behaviour state
7. Sensor quality / interference resistance
8. Richer asteroid-response tuning
9. Predictive aiming / aim smoothing knobs
10. More reusable shot patterns

The goal is for two enemies using the same weapons and shared systems to still feel radically different through data alone.
